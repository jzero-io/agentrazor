# Token 用量限制

## 范围

系统使用一套全局默认额度，并允许管理员为单个用户覆盖配置。额度按滚动窗口统计：

- 近 5 小时额度。
- 近 7 天额度。

发送消息时，服务端在创建 Turn 前检查额度；任一有效额度耗尽时直接返回业务错误。

## 配置规则

全局配置只有一条，近 5 小时和近 7 天额度均必填且必须大于 0。

用户默认继承全局配置，可独立设置：

- 禁用 Agent：禁止该用户发起 Turn。
- 关闭近 5 小时限制：仅跳过 5 小时检查，近 7 天限制仍生效。
- 自定义近 5 小时额度：覆盖全局值。
- 自定义近 7 天额度：覆盖全局值；留空时继承全局值。

用户配置优先级为：禁用 > 关闭 5 小时限制 > 用户自定义额度 > 全局额度。

## 数据模型

仅新增 `agent_token_quota` 表，通过 `scope=global|user` 区分全局与用户配置。用户执行“重置额度”时更新 `quota_reset_at`，不删除历史 Token 明细。

额度统计起点：

- 近 5 小时：`max(now - 5h, quota_reset_at)`
- 近 7 天：`max(now - 7d, quota_reset_at)`

不修改现有 `conversation_token_usage_event` 表，额度检查直接基于累计快照按滚动窗口计算。

## 权限

- `GET /api/v1/conversation/token-quota`：Agent 认证用户，只返回当前用户数据。
- `/api/v1/manage/agent/token-quota/**`：通过 Authx/Casbin，仅 Token 消耗菜单授权的管理员可访问。
- 普通 Agent 用户不能读取或修改其他用户额度。

## 管理后台

Token 消耗页面提供全局额度设置。用户管理列表提供“Token 额度”操作，可配置、禁用、恢复全局和完全重置额度。

## Agent

左下角展示有效额度的剩余百分比。5 小时限制关闭时只展示近 7 天。点击进入“使用情况与计费”页面，展示状态、用量、额度、剩余百分比、配置来源和滚动窗口说明。
